The [idrflow integrated development environment (IDE) Helm chart](http://218.50.209.93:9001/peter/idrflow-helm-charts/-/tree/main/charts/langflow-ide) is designed to provide a complete environment for developers to create, test, and debug their flows. It includes both the idrflow API and visual editor.

## Prerequisites

- A [Kubernetes](https://kubernetes.io/docs/setup/) cluster
- [kubectl](https://kubernetes.io/docs/tasks/tools/#kubectl)
- [Helm](https://helm.sh/docs/intro/install/)

## Prepare a Kubernetes cluster

This example uses [Minikube](https://minikube.sigs.k8s.io/docs/start/), but you can use any Kubernetes cluster.

1. Create a Kubernetes cluster on Minikube:

	```shell
	minikube start
	```

2. Set `kubectl` to use Minikube:

	```shell
	kubectl config use-context minikube
	```

## Install the idrflow IDE Helm chart

1. Clone the Helm charts source repository:

	```shell
	git clone http://218.50.209.93:9001/peter/idrflow-helm-charts.git
	cd idrflow-helm-charts
	```

2. Install idrflow with the default options in the `langflow` namespace:

	```shell
	helm install langflow-ide ./charts/langflow-ide -n langflow --create-namespace
	```

3. Check the status of the pods:

	```shell
	kubectl get pods -n langflow
	```

## Access the idrflow IDE

The IDE chart creates a single Service that serves both the visual editor and API on port 7860.

1. Find the service name:

    ```shell
    kubectl get svc -n langflow
    ```

    If you installed with `helm install langflow-ide ...`, the service name is `langflow-ide-langflow-ide`.

2. Enable local port forwarding:

    ```shell
    kubectl port-forward -n langflow svc/langflow-ide-langflow-ide 7860:7860
    ```

3. Access idrflow at `http://localhost:7860`. Both the visual editor and the API (`/api/v1/...`) are served from the same URL.

## Modify your idrflow IDE deployment

You can modify the idrflow IDE Helm chart's [`values.yaml`](http://218.50.209.93:9001/peter/idrflow-helm-charts/-/blob/main/charts/langflow-ide/values.yaml) file to customize your deployment.
The following sections describe some common modifications.

If you need to set secrets, Kubernetes secrets are recommended.

### Deploy a different idrflow version

The idrflow IDE Helm chart deploys the latest idrflow version by default.

To specify a different idrflow version, set the `image.tag` value to your preferred version.
For example:

```yaml
image:
  tag: "1.0.0a59"
```

Or with the `--set` flag:

```shell
helm install langflow-ide ./charts/langflow-ide -n langflow --create-namespace --set image.tag=1.0.0a59
```

### Use an external database

The IDE chart uses the default idrflow SQLite database by default. To use an external PostgreSQL database, pass the connection URL via the `env` list:

```yaml
env:
  - name: IDRFLOW_DATABASE_URL
    value: "postgresql://user:password@postgres-host:5432/langflow"
```

Or reference a Kubernetes secret:

```yaml
env:
  - name: IDRFLOW_DATABASE_URL
    valueFrom:
      secretKeyRef:
        name: db-credentials
        key: database-url
```

For more information, see [Configure a custom database](/configuration-custom-database).

### Configure scaling

Use `replicaCount` for horizontal scaling and `resources` for vertical scaling:

```yaml
replicaCount: 3

resources:
  requests:
    cpu: 0.5
    memory: 1Gi
  limits:
    cpu: 1
    memory: 2Gi
```

:::note
If you scale horizontally (`replicaCount > 1`), you must use an external database instead of the default SQLite, because SQLite does not support concurrent access from multiple pods.
:::
